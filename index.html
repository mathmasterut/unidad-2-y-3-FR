1. Protocolos y estándares de la Capa de Red · Protocolo IPv4 e IPv6

Saber: Identificar protocolos y estándares de la Capa de Red. Describir las características básicas del protocolo IP.

🔵 Concepto

La Capa de Red es la capa 3 del modelo OSI (equivale a la capa Internet del modelo TCP/IP). Su trabajo es llevar paquetes de un dispositivo a otro aunque estén en redes distintas, eligiendo el camino a través de routers.

🟠 Analogía: el servicio de paquetería

Imagina que envías una caja de Huejutla a Monterrey. Tú no sabes por qué carreteras va a pasar; solo escribes la dirección de destino y la de remitente. La paquetería (la capa de red) decide la ruta, pasa por varios centros de distribución (los routers) y entrega. Si la caja es muy grande para un camión, la divide (fragmentación). Así funciona IP.

Las 4 funciones básicas de la capa de red

① Direccionamiento

Cada dispositivo final recibe una dirección IP única que lo identifica dentro de la red (como el domicilio de una casa).

② Encapsulamiento

Recibe el segmento de la capa de transporte y le agrega un encabezado IP con origen y destino. El resultado se llama paquete.

③ Enrutamiento

Los routers eligen el mejor camino para que el paquete llegue a la red destino. Cada router atravesado es un salto (hop).

④ Desencapsulamiento

Al llegar, el destino revisa que la IP sea la suya, quita el encabezado y entrega el contenido a la capa de transporte.

Características básicas del protocolo IP

🔌 Sin conexión

No “marca” antes de enviar ni establece una sesión con el destino. Simplemente manda el paquete.

🎯 Máximo esfuerzo (best effort)

Hace lo posible por entregar, pero no garantiza que llegue, ni el orden, ni avisa si se pierde. De eso se encarga TCP (capa 4) si se necesita.

🧩 Independiente del medio

Funciona igual sobre cobre, fibra, Wi-Fi o satélite. Solo debe respetar el tamaño máximo (MTU) de cada medio.

🟠 Analogía: carta ordinaria vs. llamada

IP es como echar una carta al buzón: no le hablas antes al destinatario (sin conexión), el correo hace su mejor esfuerzo pero no te avisa si se pierde (best effort), y da igual si viaja en avión o camión (independiente del medio).

2. Introducción al enrutamiento · MAC e IP

Saber: Identificar los componentes de hardware y software de un router. Identificar los criterios, factores y elementos que permiten la interconexión de redes de datos.

🔵 Concepto

Un router (ruteador o enrutador) es un dispositivo de capa 3 que conecta redes diferentes y decide hacia dónde reenviar cada paquete según la dirección IP de destino y su tabla de enrutamiento. Un switch, en cambio, conecta dispositivos dentro de la misma red usando direcciones MAC.

🟠 Analogía: la caseta de cobro y los letreros de carretera

El router es como un cruce de carreteras con letreros: “Pachuca → salida 1”, “Tampico → salida 2”, “cualquier otro destino → autopista principal”. El conductor (el paquete) no conoce el camino completo; en cada cruce lee el letrero y avanza al siguiente. Esos letreros son la tabla de enrutamiento.

Software del router

  • Sistema operativo: en equipos Cisco es el IOS (Internetwork Operating System). Se maneja por línea de comandos (CLI).
  • Archivo de configuración: lista de comandos que define nombre, contraseñas, direcciones IP de interfaces, rutas, etc.
  • Protocolos de enrutamiento: programas internos (OSPF, EIGRP, RIP) que aprenden rutas automáticamente.

Proceso de arranque de un router

  1. POST (desde ROM): revisa que el hardware funcione.
  2. Bootstrap (desde ROM): busca el sistema operativo.
  3. Carga del IOS desde Flash (o TFTP si no lo encuentra) hacia la RAM.
  4. Carga de la configuración: copia startup-config de NVRAM a RAM como running-config. Si no existe, entra al diálogo de configuración inicial.

Criterios y elementos para interconectar redes

Para que dos redes se comuniquen se necesitan:

  • Un router (o switch de capa 3) con una interfaz en cada red.
  • Direccionamiento coherente: cada red con su propio identificador (no deben traslaparse).
  • Puerta de enlace predeterminada (default gateway) configurada en cada host: es la IP del router en esa red; a ella se envía todo lo que va “fuera” de la red local.
  • Tabla de enrutamiento con rutas hacia las redes remotas.
  • Medio y protocolos compatibles (Ethernet, seriales, fibra, etc.).

¿Cómo aprende rutas un router?

Directamente conectadas C

Las redes donde el router tiene una interfaz configurada y activa. Las aprende solo.

Estáticas S

Las escribe el administrador a mano. Simples y seguras, pero no se adaptan solas si falla un enlace.

Dinámicas O D R

Aprendidas por protocolos (OSPF, EIGRP, RIP). Se adaptan a cambios automáticamente.

Factores para elegir la mejor ruta

  • Coincidencia más larga (longest match): si varias rutas coinciden con el destino, gana la de prefijo más largo (la más específica).
  • Distancia administrativa (AD): qué tan confiable es la fuente. Menor es mejor: conectada = 0, estática = 1, EIGRP = 90, OSPF = 110, RIP = 120.
  • Métrica: “costo” de la ruta según el protocolo (saltos en RIP, ancho de banda en OSPF).

3. ARP · Protocolo de Resolución de Direcciones

Saber: Identificar qué es y cómo funciona el Protocolo de Resolución de Direcciones.

🔵 Concepto

ARP (Address Resolution Protocol) sirve para descubrir la dirección MAC que corresponde a una dirección IPv4 conocida dentro de la misma red local. Es necesario porque, para enviar una trama Ethernet, se requiere la MAC de destino, pero las aplicaciones solo conocen la IP.

🟠 Analogía: preguntar en el salón

Llegas a un salón con un paquete para “la persona con lugar 23”, pero no sabes quién es. Gritas a todos: “¿Quién está en el lugar 23?” (broadcast). Todos escuchan, pero solo Ana responde directamente: “Yo, soy Ana” (respuesta unicast). Anotas en tu libreta “lugar 23 = Ana” (caché ARP) para no volver a gritar la próxima vez.

Funcionamiento paso a paso

PC-A (192.168.1.10, MAC AA:AA:AA:AA:AA:AA) quiere enviar datos a PC-B (192.168.1.20) en la misma red.

  1. PC-A revisa su tabla (caché) ARP. ¿Ya conoce la MAC de 192.168.1.20? Si sí, la usa y termina.
  2. Si no, envía una Solicitud ARP en broadcast (MAC destino FF:FF:FF:FF:FF:FF): “¿Quién tiene 192.168.1.20? Responde a 192.168.1.10”.
  3. El switch reenvía la trama por todos sus puertos. Todos los equipos la reciben y comparan la IP con la suya.
  4. Solo PC-B coincide y envía una Respuesta ARP en unicast: “192.168.1.20 está en BB:BB:BB:BB:BB:BB”.
  5. PC-A guarda el par IP–MAC en su caché (temporalmente, unos minutos) y ya puede enviar la trama.

¿Y si el destino está en otra red?

PC-A no pregunta por la MAC del destino remoto (el broadcast no cruza routers). Primero compara la IP destino con su máscara; si es de otra red, hace ARP por la MAC de su puerta de enlace (el router) y le entrega la trama a él.

🔴 Cuidado: problemas de ARP
  • Exceso de broadcasts: en redes muy grandes, muchos ARP saturan la red → solución: dividir en subredes/VLAN.
  • ARP spoofing (envenenamiento ARP): un atacante responde “yo soy el router” con su MAC, y así intercepta el tráfico (ataque man-in-the-middle). Se mitiga con Dynamic ARP Inspection en switches.
🟣 Para recordar

ARP es exclusivo de IPv4. En IPv6 esta función la hace NDP (Neighbor Discovery Protocol) con mensajes ICMPv6 Neighbor Solicitation y Neighbor Advertisement, usando multicast en lugar de broadcast.

4. Configuración básica de ruteadores

Saber: Identificar los modos de configuración de un router.

🔵 Concepto

El IOS de Cisco organiza los comandos en modos jerárquicos. Cada modo tiene un indicador (prompt) distinto y solo permite ciertos comandos. Así se evita que alguien cambie la configuración por error.

🟠 Analogía: un edificio con llaves

El modo usuario es la recepción: puedes mirar, pero no tocar. El modo privilegiado es la oficina del gerente (necesitas llave): ves todo y puedes guardar o reiniciar. El modo de configuración global es el cuarto de máquinas: ahí cambias cosas que afectan a todo el edificio. Y los submodos (interfaz, línea) son cuartos específicos dentro del cuarto de máquinas.

5.1 Estructura de una dirección IPv4

🔵 Concepto

Una dirección IPv4 tiene 32 bits, divididos en 4 octetos de 8 bits. Para que los humanos la leamos, cada octeto se escribe en decimal (0 a 255) separado por puntos: notación decimal punteada.

Toda dirección tiene dos partes: la porción de red (identifica la red, igual para todos los equipos de esa red) y la porción de host (identifica a cada equipo dentro de la red).

🟠 Analogía: el número telefónico

En el número 771-555-1234, la lada 771 indica la ciudad (porción de red) y 555-1234 indica la casa (porción de host). Todos los teléfonos de Pachuca comparten la lada; lo que cambia es el resto. La máscara de subred es la regla que dice “cuántos dígitos son lada”.

Conversión decimal ↔ binario

Cada bit de un octeto tiene un valor posicional. Para convertir, se suman los valores donde hay un 1:

Bit76543210
Valor1286432168421
75 =01001011

75 = 64 + 8 + 2 + 1 → 01001011. Método rápido: ¿cabe 128 en 75? No → 0. ¿Cabe 64? Sí → 1, sobran 11. ¿32? No. ¿16? No. ¿8? Sí → sobran 3. ¿4? No. ¿2? Sí → sobra 1. ¿1? Sí.

192.168.10.75 = 11000000.10101000.00001010.01001011 192 168 10 75

🔵 Concepto

La máscara de subred es otro número de 32 bits donde los 1 marcan la porción de red y los 0 la porción de host. Los unos siempre van juntos a la izquierda. Se escribe en decimal (255.255.255.0) o como prefijo, contando los unos: /24.

5.3 Tipos de direcciones IPv4

Según el destino de la comunicación

Unicast (uno a uno)

De un host a otro host específico. Ej.: tu PC a un servidor web.

Broadcast (uno a todos)

A todos los equipos de la red local. Ej.: 192.168.10.255 en una /24, o 255.255.255.255. Los routers no lo reenvían.

Multicast (uno a un grupo)

A un grupo suscrito. Rango 224.0.0.0 – 239.255.255.255. Ej.: 224.0.0.5 (routers OSPF).

🟠 Analogía

Unicast = mensaje privado de WhatsApp. Broadcast = aviso por el altavoz de la escuela: lo oyen todos. Multicast = mensaje al grupo de WhatsApp “Redes 3°A”: solo lo reciben los que están en el grupo.

Públicas y privadas

Las direcciones públicas son únicas en todo Internet y las asigna el proveedor (ISP). Las privadas (RFC 1918) se usan libremente dentro de casas, escuelas y empresas; no se enrutan en Internet, por lo que el router usa NAT para traducirlas a una pública al salir.

5.4 Segmentación de la red: ¿por qué dividir?

🔵 Concepto

Segmentar es dividir una red grande en redes más pequeñas (subredes). Cada subred es su propio dominio de broadcast: los broadcasts (como ARP) no salen de ella.

✅ Beneficios

• Menos tráfico de broadcast → mejor rendimiento.
• Seguridad: se controla qué subred habla con cuál.
• Organización: una subred por área, piso o laboratorio.
• Aprovechamiento de direcciones.
• Los problemas quedan aislados.

🟠 Analogía: la escuela y sus salones

Si toda la escuela estuviera en un solo salón gigante, cuando alguien hablara todos se interrumpirían. Dividirla en salones (subredes) hace que cada grupo trabaje sin molestar a los demás, y los pasillos (router) conectan los salones.

5.5 División en subredes paso a paso (FLSM)

🔵 Concepto

Para crear subredes se “piden prestados” bits de la porción de host y se convierten en bits de subred. Con FLSM (Fixed Length Subnet Mask) todas las subredes quedan del mismo tamaño.

  • Número de subredes = 2n (n = bits prestados)
  • Hosts por subred = 2h − 2 (h = bits que quedan para host)
  • Salto = 256 − valor de la máscara en el octeto “interesante”
🟢 Ejemplo 1 · 192.168.10.0/24 → 4 laboratorios

Problema: La universidad tiene la red 192.168.10.0/24 y necesita 4 subredes, una por laboratorio.

  1. ¿Cuántos bits pedir prestados? 2n ≥ 4 → n = 2 (22 = 4).
  2. Nuevo prefijo: /24 + 2 = /26 → máscara 255.255.255.192.
  3. Hosts por subred: quedan 32 − 26 = 6 bits → 26 − 2 = 62 hosts.
  4. Salto: 256 − 192 = 64. Las subredes empiezan en .0, .64, .128, .192.

5.6 VLSM · Máscaras de subred de longitud variable

🔵 Concepto

Con FLSM todas las subredes son iguales, y eso desperdicia direcciones: un enlace entre dos routers solo necesita 2 IP, pero con /26 le daríamos 62. VLSM permite usar una máscara diferente para cada subred, según el número de hosts que necesita. Es como “subdividir una subred”.

🟠 Analogía: cortar una pizza para invitados distintos

Con FLSM cortas la pizza en 8 rebanadas iguales aunque uno coma mucho y otro casi nada. Con VLSM cortas a la medida: una rebanada grande para quien tiene más hambre, y rebanadas pequeñas para los demás. Regla de oro: primero se sirve al que necesita más.

6. Direccionamiento IPv6

Saber: Identificar las características de una dirección IPv6 y su relación con el prefijo de red. Identificar los tipos de direcciones IPv6. Describir los servicios “stateful” y “stateless” en direcciones IPv6. Describir el proceso de división de redes IPv6 en subredes.

🔵 ¿Por qué IPv6?

IPv4 tiene ~4,300 millones de direcciones y ya se agotaron (LACNIC entregó sus últimos bloques en 2020). Se “parchó” con NAT y direcciones privadas, pero eso complica la comunicación extremo a extremo. IPv6 usa 128 bits:

2128 = 340,282,366,920,938,463,463,374,607,431,768,211,456 direcciones

🟠 Analogía: los granos de arena

Si IPv4 fuera una cubeta de arena, IPv6 sería todas las playas y desiertos de miles de planetas como la Tierra. Por eso en IPv6 ya no se “ahorran” direcciones: cada red local recibe 18 trillones de direcciones (/64) aunque tenga 20 computadoras.

  • No distingue mayúsculas de minúsculas (se recomienda minúsculas).

Unicast · en detalle

🌎 Global Unicast (GUA)

• Equivalente a una IP pública de IPv4: única en todo el mundo y enrutable en Internet.
• Actualmente se asignan las que inician con 2 o 3 (2000::/3).
• Estructura: prefijo global + ID de subred + ID de interfaz (ver 6.2).
• 2001:db8::/32 está reservada para documentación y ejemplos (como en este material y Packet Tracer).

🔗 Link-Local (LLA)

• Inician con fe80. Solo sirven dentro del mismo enlace (mismo segmento/VLAN); los routers no las reenvían.
• Obligatorias: toda interfaz con IPv6 tiene una, y se crea sola al activar IPv6.
• Se usan para NDP, para los anuncios de router y como puerta de enlace de los hosts.
• Pueden repetirse en enlaces distintos (por eso Windows agrega %12, el número de interfaz).

🏫 Unique Local (ULA)

• Inician con fd (fc00::/7 con el bit L = 1 → fd00::/8).
• Equivalentes a las privadas de IPv4 (10.x, 192.168.x): para comunicación interna, no se enrutan en Internet.
• Incluyen un ID global aleatorio de 40 bits para que sea casi imposible que dos organizaciones coincidan (útil si se fusionan o conectan por VPN).

🔁 Loopback y no especificada

• ::1 = el propio equipo (como 127.0.0.1).
• :: = “sin dirección”; se usa como origen mientras el equipo obtiene una (por ejemplo, al verificar duplicados).
• ::ffff:192.0.2.1 = IPv4 representada dentro de IPv6 (transición).

6.4 ¿Qué tipo de dirección se usa comúnmente en una red local?

🟣 Respuesta corta

  1. Link-local (fe80::/10) → siempre, automática y obligatoria. Sirve para hablar con los vecinos y con el router (la puerta de enlace del host suele ser la LLA del router).
  2. Global unicast (GUA) en un prefijo /64 → la más común para redes locales con salida a Internet. El router anuncia el prefijo /64 y el host completa su ID de interfaz (SLAAC) o la recibe de DHCPv6.
  3. Unique local (ULA, fd00::/8) en /64 → para redes internas sin salida a Internet, laboratorios o servicios internos (impresoras, servidores) que se quieren mantener privados. Es la “equivalente” a 192.168.x.x.

6.5 El ID de interfaz: cómo se genera la parte del host

Los 64 bits del ID de interfaz pueden obtenerse de cuatro maneras:

✍️ Manual (estática)

El administrador la escribe. Se usa en routers y servidores para que sean fáciles de recordar: 2001:db8:acad:1::1.

🔢 EUI-64

Se construye a partir de la MAC de 48 bits. Es predecible (la MAC queda visible).

🎲 Aleatoria

Windows, macOS, Android e iOS generan IDs aleatorios (direcciones de privacidad, RFC 4941/7217) para que no se pueda rastrear al equipo por su MAC.

🖥️ DHCPv6

Un servidor entrega la dirección completa (modo stateful).

🟢 Ejemplo paso a paso: EUI-64 con la MAC 00:1A:2B:3C:4D:5E
  1. Dividir la MAC a la mitad: 00:1A:2B | 3C:4D:5E
  2. Insertar FF:FE en medio (así se completan 64 bits): 00:1A:2B:FF:FE:3C:4D:5E
  3. Invertir el 7.º bit (bit U/L) del primer byte:
    00 = 0000 0000 → 0000 0010 = 02
  4. Agrupar en hextetos: 021a:2bff:fe3c:4d5e
  5. Unir con el prefijo:
    LLA: fe80::21a:2bff:fe3c:4d5e
    GUA (prefijo anunciado 2001:db8:acad:1::/64): 2001:db8:acad:1:21a:2bff:fe3c:4d5e

🔎 Truco: si ves ff:fe en medio del ID de interfaz, esa dirección se generó con EUI-64.

6.6 Servicios “stateful” y “stateless” en IPv6

🔵 Concepto

Un servicio stateful (“con estado”) lleva un registro de qué dirección entregó a cada equipo (como DHCP en IPv4). Un servicio stateless (“sin estado”) no guarda registro: el router solo anuncia el prefijo y cada equipo se configura solo.

🟠 Analogía: la colonia nueva

Stateless (SLAAC): el municipio pone un letrero “Esta es la calle Morelos” (el prefijo). Cada vecino elige su propio número de casa, verifica que nadie más lo tenga y listo. El municipio no lleva lista.
Stateful (DHCPv6): el municipio tiene una oficina que asigna el número a cada vecino y lo apunta en un libro de registro.

¿Cómo empieza todo? Mensajes RS y RA (ICMPv6)

  1. El host se conecta y crea su LLA (fe80::…).
  2. Envía una Router Solicitation (RS) a ff02::2 (todos los routers): “¿hay algún router aquí?”.
  3. El router responde con un Router Advertisement (RA) a ff02::1 que contiene: prefijo /64, su LLA como gateway y banderas que indican el método a usar.
  4. El host aplica el método indicado y realiza DAD (Duplicate Address Detection): pregunta si alguien ya usa esa dirección antes de usarla.

6.7 División de redes IPv6 en subredes · paso a paso

🔵 La gran diferencia con IPv4
  • En IPv4 se roban bits de host y hay que cuidar cada dirección. En IPv6 no se tocan los 64 bits de interfaz: se usan los bits del ID de subred que están entre el prefijo global y el /64.
  • No hay dirección de broadcast; no se “restan 2”.
  • Fórmulas: subredes = 2(prefijo nuevo − prefijo original) · direcciones por subred = 2(128 − prefijo).
  • Lo más fácil es dividir en límites de nibble (múltiplos de 4 bits: /48, /52, /56, /60, /64), porque así cada subred cambia un dígito hexadecimal completo.
🟢 Ejemplo 1 · 2001:db8:acad::/48 → subredes /64 (el caso más común)

Problema: La universidad recibió 2001:db8:acad::/48 de su ISP. Debe crear una subred por cada área.

  1. Expandir el prefijo para ver cada bit: 2001:0db8:acad:0000:0000:0000:0000:0000
  2. Bits de subred: 64 − 48 = 16 bits = el 4.º hexteto completo.
  3. Número de subredes: 216 = 65,536 subredes /64 (de 0000 a ffff).
  4. Direcciones por subred: 264 = 18,446,744,073,709,551,616.
  5. Generar subredes: se cuenta en hexadecimal en el 4.º hexteto: 0, 1, 2 … 9, a, b … f, 10, 11 …

El ISP entrega 2001:db8:beef:3400::/56. ¿Cuántas redes puedo crear y cuáles son?

7. ICMP · Protocolo de Mensajes de Control de Internet

Saber: Identificar las características y funciones del protocolo ICMP.

🔵 Concepto

Como IP es de “máximo esfuerzo” y no avisa de problemas, existe ICMP: un protocolo que transporta mensajes de error y de diagnóstico entre dispositivos. ICMP viaja dentro de un paquete IP (protocolo número 1). Para IPv6 existe ICMPv6, que además incluye las funciones de NDP (reemplazo de ARP) y la autoconfiguración.

🟠 Analogía: el acuse del correo

ICMP es como el aviso de la paquetería: “su envío fue devuelto: domicilio inexistente” (destino inalcanzable), “el paquete excedió el tiempo de tránsito” (tiempo excedido) o “sí, el destinatario está ahí” (respuesta de eco).

La capa de transporte y los puertos

La capa de transporte lleva los datos de una aplicación a otra aplicación (no solo de equipo a equipo). Para saber a qué aplicación entregar, usa números de puerto (16 bits: 0 – 65,535).

🟠 Analogía: el edificio de departamentos

La dirección IP es la dirección del edificio; el puerto es el número de departamento. El cartero (IP) lleva la carta al edificio correcto, pero el conserje (transporte) la entrega al departamento 80 (servidor web) o al 25 (correo). La combinación IP + puerto se llama socket: 192.168.1.10:80.

Puertos bien conocidos

0 – 1023. Servicios estándar: 80 HTTP, 443 HTTPS, 53 DNS, 22 SSH.

Puertos registrados

1024 – 49151. Aplicaciones específicas: 3306 MySQL, 3389 Escritorio remoto.

Puertos dinámicos / privados

49152 – 65535. El cliente elige uno temporal como origen para cada conexión.

2. Protocolos de Capas de Aplicación, Presentación y Sesión

Saber: Identificar la función de la capa de Aplicación, Presentación, Sesión y su interrelación.

7 · Aplicación

Es la interfaz entre el usuario (sus programas) y la red. Define cómo las aplicaciones piden y reciben servicios: navegar, enviar correo, transferir archivos, resolver nombres.

Protocolos: HTTP, DNS, SMTP, FTP, DHCP.

6 · Presentación

Se encarga del formato de los datos para que ambos extremos los entiendan:
• Codificación/conversión (ASCII, UTF-8)
• Compresión (JPEG, MP3, MP4, ZIP)
• Cifrado (TLS/SSL)

5 · Sesión

Abre, mantiene y cierra el “diálogo” entre aplicaciones. Controla turnos, puntos de sincronización y reanudación. Ej.: mantener tu sesión iniciada en la plataforma escolar, reanudar una descarga.

🟠 Analogía: una videoconferencia con intérprete

Aplicación = la plataforma de reuniones que usas (lo que ves y con lo que interactúas).
Presentación = el intérprete que traduce del inglés al español, y además comprime tu voz y la cifra para que nadie la espíe.
Sesión = el moderador que abre la reunión, da la palabra por turnos, y si alguien se desconecta le permite volver a entrar donde se quedó.

Interrelación: cómo trabajan juntas

Cuando abres https://www.uthh.edu.mx en el navegador:

  1. Aplicación: el navegador genera una petición HTTP GET para la página.
  2. Presentación: la petición se codifica (UTF-8), puede comprimirse (gzip) y se cifra con TLS (la “S” de HTTPS).
  3. Sesión: se establece y mantiene la sesión TLS y se gestionan cookies/tokens para que el servidor “recuerde” quién eres entre una página y otra.
  4. Se entrega a Transporte (TCP puerto 443) y baja por las demás capas. En el servidor, el proceso es inverso: sesión, descifrado y presentación de los datos a la aplicación web.

Modelos de interacción

Cliente–servidor

El cliente solicita y el servidor (siempre encendido, con dirección conocida) responde. Ej.: navegador y servidor web, cliente de correo y servidor de correo.

Peer-to-peer (P2P)

Cada equipo puede actuar como cliente y servidor al mismo tiempo, sin un servidor central. Ej.: BitTorrent, compartir carpetas en una red pequeña.

DNS · Sistema de Nombres de Dominio

🔵 Concepto

Las personas recordamos nombres (www.uthh.edu.mx); las computadoras necesitan IP. DNS traduce nombres a IP. Es una base de datos jerárquica y distribuida: raíz (.) → dominios de nivel superior (.mx, .com) → dominios (uthh.edu.mx) → hosts (www).

🟠 Analogía: la agenda del celular

Tú buscas “Mamá” y el celular marca el número. DNS es la agenda de contactos de Internet.

  1. Escribes www.uthh.edu.mx. La PC revisa su caché.
  2. Si no lo tiene, pregunta a su servidor DNS (resolvedor) configurado.
  3. El resolvedor consulta a un servidor raíz → le dice dónde están los de .mx → estos le dicen dónde está el de uthh.edu.mx → este responde con la IP.
  4. El resolvedor entrega la IP a la PC y la guarda en caché.

DHCP · Protocolo de Configuración Dinámica de Host

🔵 Concepto

DHCP entrega automáticamente a cada equipo: dirección IP, máscara, puerta de enlace y servidores DNS, por un tiempo limitado llamado arrendamiento (lease). Evita configurar a mano cientos de equipos y los conflictos de IP duplicadas.

Proceso DORA:

D · Discover

El cliente (sin IP, origen 0.0.0.0) grita en broadcast: “¿Hay algún servidor DHCP?”

O · Offer

El servidor ofrece: “Te propongo 192.168.10.150 por 8 horas”.

R · Request

El cliente responde: “Acepto la 192.168.10.150” (en broadcast, para que otros servidores sepan que no aceptó su oferta).

A · Acknowledge

El servidor confirma: “Listo, es tuya”, y la registra.

🟠 Analogía: el hotel

Llegas a la recepción (Discover), te ofrecen la habitación 150 (Offer), dices “la tomo” (Request) y te dan la llave por 3 noches (Acknowledge). Al terminar el tiempo, renuevas o la devuelves.

FTP y TFTP

FTP · File Transfer Protocol

• TCP, con dos conexiones: puerto 21 control (comandos) y 20 datos (archivos).
• Requiere usuario y contraseña (o anónimo).
• Permite listar, subir, bajar, renombrar y borrar.
• Envía credenciales sin cifrar; alternativas seguras: SFTP (sobre SSH) o FTPS.

TFTP · Trivial FTP

• UDP puerto 69, muy simple y ligero.
• Sin autenticación y sin listar directorios.
• Uso típico: respaldar o cargar el IOS y configuraciones de routers/switches, arranque de equipos por red (PXE).

R1# copy running-config tftp:
Address or name of remote host []? 192.168.10.10
Destination filename [r1-confg]? R1-respaldo.cfg
!!
1234 bytes copied in 0.5 secs

Telnet y SSH

Telnet (TCP 23) permite administrar equipos a distancia por línea de comandos, pero envía todo en texto plano, incluida la contraseña: cualquiera que capture el tráfico (por ejemplo con Wireshark) la puede leer. Por eso hoy se usa SSH (TCP 22), que cifra la sesión.

🟠 Analogía

Telnet es dar tus instrucciones gritando por el pasillo; SSH es dárselas en clave secreta que solo el otro entiende.

P2P · Peer-to-peer

🔵 Concepto

En las redes P2P los equipos (pares o peers) comparten recursos directamente entre sí, sin depender de un servidor central. Cada par es cliente y servidor a la vez.

Ventajas

• Económica: no requiere servidor dedicado.
• Escalable: más usuarios = más fuentes de descarga.
• Sin punto único de falla.

Desventajas

• Difícil de administrar y asegurar.
• Riesgo de malware y contenido ilegal.
• Rendimiento depende de los pares conectados.

🟠 Analogía: intercambio de apuntes

En lugar de que todos saquen copias en la papelería (servidor), cada alumno pasa las hojas que tiene a sus compañeros y recibe las que le faltan. BitTorrent funciona así: descargas pedazos de un archivo desde muchos pares y, al mismo tiempo, compartes los que ya tienes.

4. Seguridad, confiabilidad y buenas prácticas en la implementación de redes

Saber: Identificar los fundamentos de seguridad de una red de datos. Describir las características de confiabilidad de una red. Identificar buenas prácticas de seguridad en la red.

Fundamentos de seguridad: la triada CIA

🔒 Confidencialidad

Solo las personas autorizadas pueden ver la información. Herramientas: cifrado, contraseñas, control de acceso.

✅ Integridad

La información no se altera sin autorización. Herramientas: funciones hash, firmas digitales.

🟢 Disponibilidad

Los servicios están accesibles cuando se necesitan. Herramientas: redundancia, respaldos, protección contra DoS.

🟠 Analogía: el examen final

Confidencialidad: nadie debe ver el examen antes de tiempo. Integridad: nadie debe cambiar las respuestas ni las calificaciones. Disponibilidad: el examen debe estar listo el día y hora acordados.

Amenazas comunes

AmenazaDescripción
Malware (virus, gusanos, troyanos, ransomware)Software malicioso que daña, espía o secuestra información.
Phishing / ingeniería socialEngañar al usuario (correos falsos) para que entregue contraseñas o datos.
Denegación de servicio (DoS/DDoS)Saturar un servidor para que deje de responder.
Intermediario (Man-in-the-middle)Interceptar la comunicación (por ejemplo con ARP spoofing).
ReconocimientoEscaneo de puertos y hosts para buscar vulnerabilidades.
Acceso no autorizadoContraseñas débiles o por defecto, puertos abiertos innecesarios.
Amenazas internasUsuarios de la propia organización, por error o con mala intención.

Características de una red confiable

🛡️ Tolerancia a fallas

Si un enlace o equipo falla, la red sigue funcionando por caminos redundantes. Ej.: dos enlaces a Internet, dos switches de núcleo.

📈 Escalabilidad

Puede crecer (más usuarios, más servicios) sin afectar a los actuales. Ej.: diseño jerárquico y un buen plan de direccionamiento.

🚦 Calidad de servicio (QoS)

Da prioridad al tráfico sensible (voz, video) sobre el que puede esperar (descargas, correo).

🔐 Seguridad

Protege la infraestructura (equipos, cuartos de telecom) y la información (triada CIA).

🟠 Analogía: la red de carreteras

Tolerancia a fallas = si cierran la autopista hay carreteras alternas. Escalabilidad = se pueden construir más carriles sin cerrar la carretera. QoS = carril exclusivo para ambulancias. Seguridad = casetas, vigilancia y reglas de tránsito.

Buenas prácticas de seguridad en la red

Dispositivos de red

• Cambiar usuarios/contraseñas por defecto.
• enable secret y service password-encryption.
• Usar SSH en lugar de Telnet.
• Apagar puertos e interfaces que no se usan (shutdown).
• Banner de advertencia legal.
• Actualizar el firmware/IOS.
• Respaldar configuraciones (TFTP).

Red y servicios

• Firewall y listas de control de acceso (ACL).
• Segmentar con subredes y VLAN (alumnos, docentes, administración, invitados).
• Wi-Fi con WPA2/WPA3 y red separada para invitados.
• Preferir protocolos seguros: HTTPS, SFTP, SSH, IMAPS.
• Monitoreo y registros (logs, Syslog).

Usuarios

• Contraseñas largas y únicas; autenticación de dos factores.
• Capacitación contra phishing.
• Principio de mínimo privilegio: cada quien solo accede a lo que necesita.

Físico y continuidad

• Cuartos de telecomunicaciones cerrados con llave.
• UPS (no-break) y protección eléctrica.
• Respaldos periódicos (regla 3-2-1: 3 copias, 2 medios, 1 fuera del sitio).
• Documentar la red (topología y tabla de direccionamiento).

Unidad II

1. ¿Qué componente del router guarda la startup-config y cuál la running-config?

NVRAM guarda la startup-config (no se borra al apagar). RAM guarda la running-config (se pierde al apagar si no se guarda).

2. Una PC con 192.168.1.10/24 quiere enviar datos a 10.0.0.5. ¿De quién pide la MAC por ARP?

De su puerta de enlace (el router), porque el destino está en otra red. El broadcast ARP no cruza routers.

3. Divide 192.168.100.0/24 en 8 subredes. Indica prefijo, máscara, hosts por subred y la 3.ª subred completa.

23 = 8 → /27, máscara 255.255.255.224, 25 − 2 = 30 hosts, salto 32.
Subredes: .0, .32, .64, .96, .128, .160, .192, .224.
3.ª subred (índice 2): red 192.168.100.64/27, hosts .65 – .94, broadcast .95.

4. ¿A qué red pertenece 172.16.45.200/20? ¿Cuál es su broadcast?

Máscara 255.255.240.0; tercer octeto 45 → múltiplo de 16 inferior = 32. Red 172.16.32.0/20, broadcast 172.16.47.255, hosts 172.16.32.1 – 172.16.47.254.

5. Con VLSM sobre 10.10.10.0/24 asigna: A = 60 hosts, B = 28 hosts, C = 12 hosts, enlace WAN = 2 hosts.

A: 10.10.10.0/26 (.1 – .62, bc .63) · B: 10.10.10.64/27 (.65 – .94, bc .95) · C: 10.10.10.96/28 (.97 – .110, bc .111) · WAN: 10.10.10.112/30 (.113 – .114, bc .115).

6. Comprime: 2001:0db8:0000:0000:0000:0000:0bad:0001

2001:db8::bad:1

7. Expande: fe80::a:0:1

Hay 5 hextetos → faltan 3 de ceros: fe80:0000:0000:0000:0000:000a:0000:0001. (Primero fe80, luego 3 hextetos de ceros por el ::, y después a, 0, 1).

8. Clasifica: (a) fd12:3456:789a:1::5 (b) fe80::1 (c) 2800:3f0:4001::200e (d) ff02::2

(a) ULA (privada interna) · (b) Link-local · (c) Global unicast (pública) · (d) Multicast “todos los routers”.

9. Una empresa recibe 2001:db8:cafe::/48. ¿Cuántas subredes /64 puede crear? Escribe la 1.ª, la 11.ª y la última.

216 = 65,536. 1.ª: 2001:db8:cafe:0::/64 · 11.ª (ID 10 decimal = a hex): 2001:db8:cafe:a::/64 · última: 2001:db8:cafe:ffff::/64.

10. Genera la LLA por EUI-64 para la MAC 00:50:56:AB:CD:EF.

00:50:56 | FF:FE | AB:CD:EF → invertir 7.º bit de 00 → 02 → fe80::250:56ff:feab:cdef.

11. Un RA llega con M = 0 y O = 1. ¿Cómo obtiene el host su dirección y su DNS?

Dirección por SLAAC (prefijo del RA + su ID de interfaz) y DNS por DHCPv6 sin estado.

12. ¿Qué mensaje ICMP aprovecha traceroute y por qué?

Tiempo excedido (tipo 11): al enviar paquetes con TTL creciente, cada router que lo reduce a 0 responde con este mensaje y revela su dirección.

Unidad III

13. ¿Qué protocolo de transporte usarías para una videollamada y para descargar un PDF? ¿Por qué?

Videollamada: UDP (prioriza tiempo real; perder un cuadro no importa). PDF: TCP (el archivo debe llegar completo y en orden).

14. Ordena los mensajes DHCP y di cuáles son broadcast.

Discover → Offer → Request → Acknowledge. En IPv4, Discover y Request se envían en broadcast (el cliente aún no tiene IP); Offer y Ack pueden ser broadcast o unicast según el cliente.

15. ¿Qué capa OSI se encarga del cifrado y la compresión?

La capa de Presentación (6).

16. Un usuario lee su correo en celular y laptop y quiere ver lo mismo en ambos. ¿POP3 o IMAP?

IMAP, porque mantiene los mensajes y su estado sincronizados en el servidor.

17. ¿Por qué se recomienda SSH en lugar de Telnet?

Telnet envía todo en texto plano (incluidas las contraseñas); SSH cifra la sesión, protegiendo la confidencialidad.

18. Menciona las 4 características de una red confiable.

Tolerancia a fallas, escalabilidad, calidad de servicio (QoS) y seguridad.

Glosario rápido

ACL: lista de reglas que permite o deniega tráfico en un router.

Anycast: una dirección compartida por varios equipos; responde el más cercano.

ARP: obtiene la MAC a partir de una IPv4.

Broadcast: envío a todos los equipos de la red local (no existe en IPv6).

CIDR: notación /n sin clases para indicar el prefijo.

DAD: detección de direcciones duplicadas en IPv6.

Default gateway: IP del router al que el host envía el tráfico de otras redes.

EUI-64: método para formar el ID de interfaz IPv6 a partir de la MAC.

GUA: dirección IPv6 global unicast (pública).

Hexteto: grupo de 16 bits (4 dígitos hex) de una IPv6.

IOS: sistema operativo de los equipos Cisco.

LLA: dirección IPv6 de enlace local (fe80::/10).

MTU: tamaño máximo de paquete que admite un medio.

NAT: traduce direcciones privadas a públicas.

NDP: protocolo de descubrimiento de vecinos de IPv6 (reemplaza a ARP).

Nibble: 4 bits = un dígito hexadecimal.

Prefijo: cantidad de bits que identifican la red (/24, /64).

RA / RS: anuncio y solicitud de router (ICMPv6).

SLAAC: autoconfiguración de direcciones sin estado en IPv6.

Socket: combinación IP + puerto.

TTL / Hop Limit: número máximo de saltos de un paquete.

ULA: dirección IPv6 única local (privada, fd00::/8).

VLSM: subredes con máscaras de distinto tamaño.
